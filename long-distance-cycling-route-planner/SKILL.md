# 长距离骑行路线规划器

把已有路线设想转换为可实际执行的骑行计划，适用于不使用码表、行者等专用路书设备，主要依靠手机导航和交互地图辅助定位的骑手。交互地图请求的交付物是从实际起点到实际终点的完整道路路线，不是仅把 GPX 画在底图上。

## 默认规则

- 在中国大陆，默认使用高德地图进行地点检索、道路骑行规划、坐标链接和分段导航；用户明确指定其他平台时除外。
- 用户未说明行程天数时，默认按一天规划。如果一天完成明显不安全或不现实，应明确指出，并提供决策点、撤退点和住宿选择，不得擅自把行程改成多日。
- 默认包含长距离骑行安全建议。
- 条件允许时，同时提供适合手机和电脑查看的交互地图。
- 默认采用“GPX引导、合理近似”：完整保留原GPX作路书参考，高德尽量贴近主要走廊与途经点，不要求逐点重合。两条路线同时标注，不用高德新线覆盖原GPX。用户明确要求严格保持轨迹时，才使用严格模式。
- 普通局部绕行作差异提示；遗漏必经道路或桥梁、明显抄近路、反向或无意义折返仍需核查。高德只负责导航至下一终点，段内可能重新算路。不得因每段都有文字复核就忽略全程重叠率；长路线还必须通过原GPX到高德和高德到原GPX的双向覆盖门槛。
- 尽量减少骑手手动切换导航的次数。不得把每个弯道、提示或地图标记都做成高德分段终点。

## 最少输入信息

只收集会实质影响规划的信息：

1. 原始路线材料：GPX、路书、截图、链接、指定道路或按顺序排列的地点。
2. 实际起点或大致出发区域。
3. 主路线是否必须闭环。
4. 日期或行程天数（如已确定）。
5. 平均骑行速度、已验证的最长单日距离或其他体能依据。
6. 必须经过的道路、桥梁、入口以及希望住宿的区域。

已有信息足够时直接开始，不重复询问能够推导或可安全作为可选项的信息。只有某个选择会明显改变路线时，才提出一个聚焦的问题。

只有原始 GPX、且地点检索、道路数据或拓扑/方向选择尚不可用时，可以明确进入 [GPX-only 参考预览](references/gpx-only-preview.md)。此模式只为先查看原文件几何；缺少的起点、拓扑和方向保持未知，不按文件顺序推断行程，不替代上述完整规划输入。

## 确定路线与距离依据

新路书、新窗口或独立复测先读 [原始输入生成流程](references/fresh-input-workflow.md)。从原始文件和实际起点建立工作清单，不依赖旧聊天、旧地图或已审核成品；已有原始API捕获可用包内`import-api-evidence.mjs`重建候选清单，再作道路审核和删除测试。

路线证据按以下优先级使用：

1. 权威地图或导航道路网络实时生成的骑行路线。
2. 已确认是实际骑行记录或导航生成轨迹的 GPX。
3. 已注明距离来源的公开路线。
4. 根据道路和截图重建的几何线路。

直线距离、原始折线长度、截图描线或来源不明的 GPX 长度，不得称为“导航生成的骑行距离”。应说明距离来源；需要复现时注明查询日期；同时说明坐标系和所做的转换。

在中国大陆必须明确坐标系。高德使用 GCJ-02，GPX 通常使用 WGS-84。坐标转换必须有意识地进行，并检查路线叠加是否与底图道路对齐。

如果实际起点不同于路书起点，必须先决定合理接入点，并从可骑行道路网络生成实际起点到接入点的接驳几何和距离；必要返程同理。不得只放两个标记、画直线，或把接驳留给骑手点击导航后自行发现。完整主线由去程接驳、选定路书段/闭环、必要返程连续组成，每段标明里程出处。确认是实际骑行记录的 GPX 可以作为该段实骑里程，但其几何长度不能称为导航生成里程。若道路接驳、合法可骑行通道或必要距离无法核实，只能交付明确标注的研究草稿，不能声称完成地图。

当输入为 GPX 且使用原始 OSM 道路网试算时，按 [道路诊断说明](references/route-diagnostics.md) 运行随附脚本，先检查断点、异常绕行、坐标假设和接入候选。诊断器永远不输出可交付骑行里程；不能因候选路网连通就越过导航距离、路权和固定路线验收。若使用其他可信路线服务，也应对其几何进行同等异常审查。

需要高德骑行生成距离和分段地图时，读取 [高德响应组装流程](references/amap-route-assembly.md)。API批量采集先运行包内只读预检，核对组成段、低切换导航组、删除跨度及请求上限；预检不读取Key、不联网，也不授予授权。已有响应可本地复用，不因预检列出整批请求就全部重算。优先使用授权 API；没有 Key 时检查高德官方新版网页和手机网页的骑行规划，不得把“没有 API Key”直接等同于“不能算路”。组装器支持 API JSON，以及明确标注的官方手机网页记录与单独提供的道路几何；网页距离和几何同走廊的证据必须另行核实，不能把记录伪装成 API 响应。无论取证方式，均须核对接入、全线贴合、方向顺序、距离和终点删除测试。已有明确服务选择与授权时不重复索取相同确认；不得因此扩大为公开发布或其他服务披露。

外部算路暂不可用、但已有原始 OSM、已定位实际起点以及明确拓扑/方向时，仍应执行可完成的真实输入测试，按 [研究地图流程](references/research-map.md) 生成本地研究预览并在手机与电脑视口渲染。预览须展示原路书及道路接驳候选、闭环缺口和未核实项，不能只输出诊断 JSON 后称已完成；候选不得作为可骑行路线或最终方案。阻塞、实际错误和剩余验收单独记录，不能用合成测试替代真实导航验收。

如果这些 OSM 研究前提也不具备，且当前只有原始 GPX（可附一个尚未定位的起点名称），使用 [GPX-only 参考预览](references/gpx-only-preview.md) 的显式入口。该路径始终为 draft：只按原始分段显示 GPX，不连段、不闭环、不选择方向，不生成道路候选、导航终点、下一点指引或总里程。之后仍须回到 OSM 研究或高德完整流程；不得用 GPX-only 结果降低既有路径的验收要求。

## 重点标注易错途经点，同时减少导航切换

使用三种相互独立的点位：

1. **路线形状点**：用于保持固定路线折线的准确形状，可以很密集，通常不向骑手显示。
2. **沿途提示点**：用于标记经核对的关键路口、风险位置，以及补给、撤退点和地标。算法筛出的转弯先作为“转向提示候选”，不得直接称为关键点；提示点不要求重新启动高德导航。
3. **导航终点**：只保留确实需要结束上一段高德导航并启动下一段的少量关键点。

转弯角度、道路名称变化只能提出候选；只有结合固定轨迹、道路结构及走错后的后果核对过，才能标为关键路口。未核验的候选应保持可选、默认不遮挡主路线。不能因为一个点值得提示，就把它同时设为导航终点。优先把计划休息点、主要道路走廊切换点、原路线接入和离开点、高德容易绕开的桥梁或沿湖道路入口、可选支线边界设为导航终点。普通弯道、同一复杂路口附近的连续转弯、纯信息性风险点，以及并非计划停靠的补给点，应降级为沿途提示点。

默认采用低切换方案：普通一日骑行通常以约 4–8 次必要的高德切换为目标，相邻导航段一般约 15–30 km 或 45–90 分钟骑行时间。这是可用性目标，不是机械配额。只有经过固定路线对比，确认更长分段会让高德明显偏离指定道路时，才使用更短分段。不得仅按固定公里数自动增加导航终点。

选择或调整高德导航终点时，读取并执行 [导航分段规则](references/navigation-segmentation.md)。

若一段出现回头路或严重错廊，先用少量 `diagnostic_anchor` 连续探针缩小断裂范围，再合并相邻可通过跨度；诊断点本身绝不能进入完成版。最终只保留通过完整导航组、顺序/覆盖/端点返回和删除测试的 `fidelity_anchor`，以免把修路结果变成骑手频繁手动切换。

若精确短跨度探针仍产生至少5倍绕行，按 [导航分段规则](references/navigation-segmentation.md) 记录 `routeEngineGaps` 并停止无限细分。成品数据和地图必须单独显示该高德路网断点，保持草稿且禁用完整导航；不得用GPX直线补成高德路线，也不得把大量手动切换当作修复成功。

关键点重点放在经道路结构核对的易错岔路、主辅路或桥梁入口、沿湖入口和两线分离/接合处，不因转弯或距离够长就标关键点。只为触碰GPX而折返的控制点，应调整道路侧别或降为提示。普通局部差异无需反复让用户批准；改变整体环线目标、必经点或明显离开目标走廊时才提出问题。默认清单写 `alignmentMode:gpx-guided`，严格请求写 `strict`。局部偏离指标用于发现差异；但对参考线达到5公里的主线，默认还要用约20米等距采样检查双向覆盖：两侧在200米内均不少于70%，在500米内均不少于85%；任一方向连续超出200米的路段不得超过2公里，连续超出500米的路段不得超过1公里。总体比例达标也不能掩盖一段连续大偏离。单段若离开端点后提前返回，或者同时顺序不兼容且出现严重横向偏离/异常长度比例，也必须重选道路侧端点；`alignmentReview` 不能把这些折返或严重错廊豁免为完成。

可选绕行必须与主路线分开。额外距离和时间单独计算；除非用户选择该支线，否则不得混入主线累计里程。

## 制定骑行计划

- 分段距离和每日总里程使用道路网络或导航距离。
- 总耗时应包含骑行时间、正常休息、红绿灯、进餐、机械故障余量和日照限制。
- 住宿点应位于合理骑行距离且服务设施可用的位置，不能只按几何中点选择。
- 标记长距离无补给路段、暴露的沿湖路段、较差路面、车流密集区、夜骑风险、轮渡或营业时间限制，以及可实际使用的撤退点。
- 涉及具体日期时，应检查整条路线和实际骑行时段的情况，而不是只看起点天气。

当计划超过骑手已说明或已验证的能力时，保留用户要求的路线，但必须明确风险，并提供具体截止时间和撤退条件。不得把高风险行程描述成可以稳妥完成。

## 交互地图要求

无论高德预览是否可用，完整原GPX都必须独立显示，同时标注实际高德方案和道路接驳。制作交互地图前读取并执行 [地图交付契约](references/map-delivery-contract.md)，并以 [可复用地图界面](assets/map-shell.html) 为起点填充路线数据；只有用户指定另一种界面时才偏离模板。模板是通用外壳，不含任何真实路线数据。条件允许时应包含：

- 当前位置和 GPS 精度；
- 骑手距GPX原线、距高德方案分别计算并说明来源；
- 下一导航终点及其距离；
- 按高德当前方案计算剩余里程；GPX几何长度仅作路书对照；
- 日期和分段筛选；
- 住宿、补给、危险、撤退点和可选路线图层；
- 醒目的“导航至下一终点”高德按钮；
- 分开显示下一导航终点和附近沿途提示；
- 即使骑手没有逐段启动高德，也仍然可用的路线总览和提示列表。
- 地图上的每个导航分段终点使用与关键点、补给点不同的编号标记；编号与分段列表顺序一致，选择列表或点击标记时同步突出并聚焦对应分段。

GPX-only 模式只是上述地图的前置参考草稿：仍使用同一模板，但导航按钮必须禁用，详细底图和道路服务缺失须醒目标注。它不属于“高德预览不可用但已有道路候选”的情形，也不能展示虚构的路线组成或导航切换次数。

完整地图中每个高德导航段都必须有可点击链接，覆盖接驳、选定主线和必要返程；仅有接入或返程按钮不算完成。手机首屏必须看见“导航至下一终点”，不能把唯一入口放在默认折叠面板或溢出屏幕的卡片。每个链接的终点必须与地图上的对应分段一致，出发前实际检查手机视口。

如果底图瓦片、路径服务、定位权限或其他必要资源依赖网络，只能称为“在线交互地图”。只有所需地图数据和应用资源均已本地打包，并在断网状态下验证可用时，才能称为“离线地图”。

在线地图必须验证：继续放大后能够看到更多道路和地点细节。只把同一张低细节矢量快照放大，不算合格的在线底图。可以保留打包的概览图作为备用，但不得遮挡在线详细图层。

不得承诺把自定义折线锁定为高德连续语音导航。应说明分段终点能够降低偏航概率，但不能完全阻止高德重新规划。

## 隐私与安全边界

- 精确家庭地址或私人起点只能用于骑手自己的私人版本。
- 公开截图、帖子、示例和复用模板应替换为区、镇或近似区域。
- 上传完整轨迹或精确导航点属于向外部服务披露数据。只有用户明确同意上传目标和访问范围后才能执行。
- 在线底图请求也会向瓦片服务暴露当前查看区域；私人地图不能因为 HTML 保存在本地就宣称完全离线或完全不对外发送位置范围。
- 不得暴露 API 密钥、账号令牌、私人轨迹历史或住宿订单信息。
- 交互地图是辅助工具，不能保证道路开放或绝对安全。应提醒骑手服从封路信息、交通规则、天气预警和现场标志。
- 不得鼓励骑手在车辆移动时操作地图或切换导航。

## 同步更新规则

路线发生任何变化时，必须同时重新计算并更新：

- 路线几何；
- 分段、单日、可选支线和总距离；
- 累计公里标记；
- 时间估算和截止时间；
- 住宿点与补给点位置；
- 下一点顺序和导航链接；
- 所有文字、截图、导出文件和公开说明。

不得只修改某一个显示数字而不检查其所有下游依赖。

## 交付要求

用户明确要求自主更新、测试不通过就继续修正直到最终版本时，先读取 [更新与验证循环](references/iteration-loop.md) 和 [可复用能力双层验收](references/reusability-acceptance.md)，建立可追溯的失败清单，每轮继续处理无需用户参与的失败。分别报告“Skill生成能力验收”和“具体路线可骑行验收”。只有通用缺陷修进 Skill；单条路线的现场/实机缺口独立保留，不无限阻塞可复用性测试。这个循环不扩大外部上传、付费服务或系统配置的授权；不能用研究草稿或单元测试通过代替路线验收。

交付时提供简明计划摘要、距离依据、导航终点与沿途提示点数量、交互地图、重要限制和未解决的假设，并说明骑手正常情况下需要切换多少次高德导航。

如果用户需要公开版本，应另外制作经过隐私处理的公开副本，与包含精确路线的私人导航版本明确区分。

声称完成前，必须读取并执行 [质量检查清单](references/quality-gates.md)。缺少道路接驳、必要返程、完整主线分段或手机上可见的高德入口时，交付状态必须为“未完成研究草稿”，并列出具体缺口；保留说明不能代替完成验收。
