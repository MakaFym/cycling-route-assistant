# 从原始材料生成，不依赖旧地图

当用户给出新路书、在新窗口运行或进行跨Agent测试时读取。旧地图、聊天结论、已填审核的旧清单不是输入前提；可以复用具备查询时间、准确起终点的原始服务响应，但必须重新建立清单并核验。

## 输入与初始化

只有 GPX、还不能定位起点或选择拓扑/方向时，不进入本页的 OSM/高德组装步骤，也不猜测缺失值；先按 [GPX-only 参考预览](gpx-only-preview.md) 生成严格不完整的分段参考草稿。取得起点和行程选择后再从本页重新初始化。

1. 解析原GPX并完整保留。明确实际起终点、坐标系、是否环线及方向；地名用已授权平台检索，不靠旧聊天补坐标。公共站点坐标不等于指定出口。缺少日期/体能不会阻止生成地图，但时间表只能说明假设，不声称已查出发日天气。
2. 没有算路结果时，从道路结构选接入和少量走廊控制点，建立待审核`legs`并运行正常高德采集流程；只有原GPX不能自动证明这些点合法可骑。不要按10公里或每次转弯生成导航任务。

   API提交前使用`fetch-amap-bicycle.mjs --manifest FILE --dry-run`本地检查全部端点、导航组及整批请求数量，不读Key、不联网。采集CLI另需明确`--max-requests N`且符合现有授权；不能因为工具能算出请求数就视作获准。预检无距离与道路批准能力，不会自动局部复用旧捕获，详见[高德组装流程](amap-route-assembly.md)。
3. 已有原始高德v5响应时，可运行包内导入器，不必另写项目专用脚本或复制旧成品清单：

```sh
node scripts/import-api-evidence.mjs --gpx INPUT.gpx --responses RAW_CAPTURE_DIR --start LAT,LON --end LAT,LON --topology loop --direction forward --queried-at ORIGINAL_QUERY_DATE --out-dir PRIVATE_JOB
node scripts/assemble-amap-map.mjs --manifest PRIVATE_JOB/manifest.json --template assets/map-shell.html --out-html PRIVATE_JOB/map.html --out-report PRIVATE_JOB/acceptance.json
```

坐标必须是WGS-84。`loop/open`、`forward/reverse`需符合用户目标；不能因为两端靠近就推断成环线。天数默认1，可用`--days`指定。响应目录为原始`leg-01.json`等，删除响应为`merge-after-01.json`等，都是两位补零。导入器从响应`route.origin/destination`逆变坐标，校验首尾和连续性，保存可移动的相对路径捕获副本；不联网、不索取Key。

原始组成响应与低切换合并响应分别留存。响应目录有`navigation-group-01.json`等时，导入器按捕获的起终点重建连续覆盖的组范围。返程起点还未到环线接入/离开边界时，标为可能混合主线尾段/返程，不能称整段纯返程；应取得独立尾段、返程响应，用navigationGroups保持一个导航任务，不能增加内部切换。未知轨迹布局仍需Agent核对，范围自动匹配不等于道路审核。

导入器只重建服务证据和候选参考，**不是自动批准路线**。最近原始顶点只用于定位GPX区间，不能当作入口合法性证明。必须查道路结构和偏离后果再标关键点；原始响应分段仍须执行删除/合并。

新版采集目录包含`manifest-with-responses.json`时，导入器只按对应响应文件恢复逐条`queriedAt`，不继承旧审核或地点答案。混合批次的合并目录也要保留每个响应自己的日期/来源，不能只改CLI的全局日期。只有无逐条记录且确知同一日期的旧捕获才统一用`--queried-at`；查询时间未知不得用生成日期或文件修改时间填造。

当日期清单为每个leg提供有效原日期时，导入CLI可以省略`--queried-at`，全局日期保持未设置，不把第一个日期套给全部记录。只提供部分日期而无已知同批次回退日期时拒绝；合并/删除捕获缺日期仍单独待核查。`import-api-evidence.mjs --help`提供固定只读用法；受限工具环境不允许它时，用Read读取本引用，不尝试wc、ls、node -e等未授权探测。研究预览的research-report.json也可作为summarize-map-job的--acceptance输入，摘要明确标local-road-research，不把几何数冒充高德distance。

环线跨原GPX首尾缺口时保留分离`referenceSpans`，主对比`referencePoints`只取较长连续原段；明确部分覆盖，不能把其最大距离当整段偏离，也不能在原图添加虚构接缝。明显差异、反向和缺必经点按正常规则处理。

合并或移动分段后，应从新跨度的原始响应重新导入/核对参考，同步`referencePoints`、`referenceSpans`、`referenceScope`及来源区间，不能只扩大一条比较线却保留旧区间。主比较线必须完整对应某一个连续区间；“不匹配区间”可能是旧元数据，也可能是非法拼接，先对照原GPX索引查明，不删除区间字段来消除报错。修正参考元数据不等于修正实际算路的折返或偏离；实际新方案和最新删除跨度仍须分别核查。

## 审核与下一步

大清单含大量坐标时，先使用包内只读摘要，不必重写临时代码或把整份坐标送进上下文：

```sh
node scripts/summarize-map-job.mjs --manifest PRIVATE_JOB/manifest.json --acceptance PRIVATE_JOB/acceptance.json --browser-results PRIVATE_JOB/qa/browser-results.json
```

三种输入可单独提供；文件尚未生成时只传已有项。摘要保留分段角色/原查询日期/参考覆盖计数、候选与正式里程、删除边界、点位分类和每视口的实际错误，不打印原坐标数组、不修改任何输入，也不批准路线。仍需按原始证据核对起终点、连续几何及具体差异。只允许固定CLI的环境应使用这个摘要加正常Read/Write完成报告，不反复尝试被禁止的node -e、shell统计或自建程序；工具拒绝与Skill缺陷分别记录，不绕过白名单。

地图与浏览器测试完成后，使用包内事实报告生成器，不手抄距离/比较数字或补造输出字段：

```sh
node scripts/write-map-report.mjs --map PRIVATE_JOB/map.html --acceptance PRIVATE_JOB/acceptance.json --browser-results PRIVATE_JOB/qa/browser-results.json --out-md PRIVATE_JOB/report-facts.zh.md --out-json PRIVATE_JOB/report-data.json
```

研究预览同样支持：map换为research-map.html，acceptance换为research-report.json。两个输出必须是新文件；保留旧报告和失败证据。组装/研究验收报告及浏览器结果都由当前脚本记录地图SHA256。验收报告缺哈希或哈希不符时须重新生成；浏览器不同哈希或状态拒绝，旧浏览器结果缺哈希只能标未绑定，需重新检查。不能手填哈希或将旧结果当新通过。

浏览器断网测试每轮使用全新或空的QA目录，不复用截图/结果目录；失败写入qa-failure.json且退出非零，不产出整轮成功结果。定位自动选段模拟的cases与skipped单独统计，全部跳过不能宣称覆盖；布局通过不是实机GPS或自动选段全面通过。事实报告保留网页显示小数位、近似值和未知舍入误差，保留独立几何来源，以及待核查的具体事项、负责方和下一操作。

事实报告分别保留原参考几何、方案折线几何、组成导航distance以及comparisonScope；partial比较不得叫整段偏离。缺少组成映射时不按数组位置猜distance。报告生成时间与原查询时间分开，字段未记录就保留未知。脚本不证明道路开放、实机、授权或所有工具尝试成功；这些用实际证据和执行日志另记。计划与推断可以另写补充说明，但不能改写或覆盖自动事实块；输入变更后重新生成新报告，别只改单个数字。不得把外部Agent的自由文本直接作为事实交付。

导入清单包含大量原始坐标，不能为了补审核信息手工重抄点列。可写一个小型`review-patch.json`，运行包内`apply-review-metadata.mjs --manifest PRIVATE_JOB/manifest.json --patch review-patch.json --out PRIVATE_JOB/reviewed.json`，再用`reviewed.json`正常组装。工具只修改明确允许的审核/提示元数据，不改坐标、距离、响应路径、查询日期、参考区间或分段组成。输出为同目录新文件，保留相对捕获路径，原清单不变。格式见[高德响应组装流程](amap-route-assembly.md)。有编辑工具的Agent也可正常修改清单，但不能因工具受限就把本已核实的少量信息只留在报告中而停止生成循环。

多次经过同一地点时，不能用首个坐标匹配决定参考区间或组范围。导入器枚举最近投影误差近似相同的原顶点出现位置，用完整组成几何和全体主段的有序评分联合选择；正反方向显式，等价的闭环首尾顶点作为别名，仍有同等解释时拒绝，不固定选第一次或最后一次。原始组合范围另外使用全部组成及组合折线核对。跨首尾缺口的参考仍分离并注明只比较较长连续段；匹配成功不证明整个走廊已审核。

组装报告的`reviewStatus`分开列出道路/走廊、最新删除测试、入口通行；审核必须有有效日期和具体证据。默认缺口归为Agent继续核查，不能一律称“需要用户现场确认”。

规划道路审核不是逐条道路的当日开放保证。结合实际骑行响应、当前详细地图、道路属性及适用的权威资料，判断道路身份、连续性和具体限制；依据相互一致且未发现具体禁行、封闭入口或许可障碍时，可以注明置信度接受用于规划，并把施工导改、临时闸口变化列为出发前动态风险。不能只凭API成功或没有反证就批准，也不能只因OSM缺少access/bicycle标签或标为track就判私有/禁行。铺装村路或慢行道路须说明实际道路结构、地图身份及接受或拒绝的综合依据；旧建设批复只能提供背景，不是当前开放证书。

已知private/no、禁止自行车、需许可、封闭闸口、实际断点或适用的明确管控，与普通动态风险分开。前者需取得合法入口或绕行证据，解决前保持草稿；后者不应仅因缺少所有道路的现场保证而无限阻塞。施工计划先定位受影响走廊和具体导改，不能把机动车保通当骑行安全证明，也不能把施工计划本身当成全线禁行。事实、推断、置信度、资料日期与现场未测分别记录，不为通过测试填造审核。

确需用户/现场/设备时可在`review.pendingChecks`填写`code`、具体`description`、`owner`和可执行`action`。owner为`agent`、`device`、`field`、`user-choice`或`account`。未解决项不能被全部true的布尔标志掩盖。需记录已穷尽的安全替代方法，不凭字段名称就转给用户。

`reviewStatus.deviceAcceptance`默认`not-tested`。桌面手机视口、URI格式检查、API成功都不算真实手机App调起或GPS通过。先完成能自主做的版本和测试说明，手机HTTPS入口按现有明确授权交付；没有托管/上传授权时保留本地文件并解释手机不能使用电脑file路径或127.0.0.1地址。不得把主机局域网HTTP定位不可靠当作实机验证成功，也不要把启动本地服务冒充已发布手机网站。

## 可复用验收

多段GPX必须明确选择轨迹或先按原始段分别规划，现有 OSM/高德导入器拒绝把断开的trkseg/rte连接成一条路；当前导入器处理已明确选择的单段，不保证自动合并多个轨迹。GPX-only 预览可以按原段分别显示，但不得把显示顺序当成已选方向或把段间空白连起来。不得用直线填补来源缺口。

GPX解析支持属性等号空格、引号与坐标字符引用，忽略注释和CDATA中的点标签；异常嵌套、未闭合段、重复坐标属性、空坐标、混合有效轨迹/路线或孤立点混入不能静默拼接。解析器不是完整XSD校验器，也不读取DTD或外部实体；需要该类声明的文件应先用可信工具导出普通GPX，再按原始分段明确选择。

解析按GPX命名空间和父路径识别轨迹；厂商扩展中同名的trkseg/trkpt不是GPX道路点。合法前缀必须有声明，混合轨迹/路线（包括根级简化点列）需明确选择，不按首次出现静默舍弃另一类来源。常见无命名空间的简化点列保留兼容；支持该格式不等于整文件通过GPX XSD校验。

运行包内`check-map-browser.mjs`完成两视口的断网壳/几何/定位行为测试；在线详细底图另用`check-map-online.mjs MAP.html PRIVATE_QA_DIR`。复用相同Playwright和Chrome环境变量，默认只放行模板高德appmaptile域名，不调用API或URI、不点击App按钮；需要已有底图查看授权。实际查看保存的overview/detail截图确认道路和POI新增，不能只数HTTP200。不同瓦片服务需明确授权与适配，不自行绕过白名单。

- 测试实际交付包的解压件，不借用工作目录中的旧脚本或带坐标模板。
- 至少一种真实路书从原文件生成；再用不同起点或不同方向测试是否存在固定索引、文件名或旧坐标依赖。
- 报告哪些是代码/规则通过、哪些是道路审核未完、哪些是真实设备未测；不因一个设备项目未测停止全部自主迭代。
- 以最新组装版本同步几何、GPX原图、距离、少量导航端点、关键点和补给分类；真实通行证据缺失仍保持草稿。
