# 可复用生成与具体路线：分别验收

更新、冻结包复测或跨 Agent 对比时读取。报告必须有两个独立结论，不把单条路线缺少现场证据等同于 Skill 的生成流程失败，也不能把软件测试通过称为路线可骑。

## Skill生成能力验收

先冻结当前包并记录版本、文件清单与哈希。测试执行者只拿解压包、原始材料、当前用户需求和必要运行环境，不提供旧地图、旧聊天、已审清单或预期答案。评估者的断言与基线保留在执行者工作目录外。至少覆盖不同实际起点、正反方向及另一份路书；包括非闭环与独立终点。合成边界输入须标 synthetic，真实原始捕获须保留查询时间。不得把其他私人路书发给已授权范围之外的服务。

逐项核对实际产物：

- 起终点、方向、拓扑和一天默认值来自当前输入，没有固定路书索引、地名或历史文件依赖。
- 完整原GPX独立保留；研究主线按指定方向组织。非闭环不擅自闭合；闭环接入不省略原段；必要接驳缺失明确列缺口，不画直线冒充道路。
- 距离与查询日期只来自相应原始证据。研究几何、OSM候选、模拟响应不能称真实导航距离；旧捕获与新起点不符时拒绝复用。
- 形状点、提示、补给与导航终点独立；不按固定公里数或每个转弯要求切换。无删除/道路证据时诚实保留候选，不编造关键点。
- 使用包内模板与脚本，实际生成HTML与报告，在手机和电脑视口运行并检查截图；不能只有“文件存在”测试。
- 有证据流程和无服务证据的研究流程均可执行；后者禁用正式导航、总里程为空并列具体缺口。准确拒绝错误输入也是正确生成行为，不要求每个测试都批准路线。
- 只有 GPX 的显式参考模式另行覆盖 GPX 1.0/1.1、多段空白、缺起点/拓扑/方向、恶意标签和畸形输入；不得出现道路候选、完整/导航/总里程宣称。它通过不代表 OSM 研究或高德完整路径通过，既有两条路径的输入与验收要求不得弱化。

报告使用“通过（明确范围）/不通过/未测”。生产脚本的已知错误必须修复并复测；条件不足的路线输出草稿不自动构成软件失败。初始无证据输入不能用于证明真实高德采集或可骑行距离。跨模型没有实际执行时写未测。

## 具体路线可骑行验收

仍按质量检查清单执行连续道路、通行与入口、实际导航距离、方向/必经点、少量导航边界、当期限制和设备等检查。明确区分资料事实、推断、置信度与未测；服务成功不等于路权通过。缺证据继续保持 draft，禁止填造 true。

给出每个缺口的证据、负责人和取得何种数据即可解除。具体路线的现场、账号或手机项目单独列为待验；不能无限等待这些项目而停止不受影响的 Skill 测试。普通规则、代码、模板或流程缺陷自主修；新的服务披露、算路预算、发布与付费仍需既有权限或新授权。

## 每轮报告最小结构

1. 冻结包版本与哈希、实际执行者及输入隔离范围。
2. 通用缺陷：复现、修复和回归状态；仅将可推广的缺陷修入包，不写入单条路线答案。
3. Skill生成能力：输入矩阵、逐项结果和产物路径，哪些证据是合成/原始捕获/实时服务。
4. 具体路线可骑行：每条路线独立状态、未核实项和负责人；不能用软件通过覆盖该状态。
5. 尚未覆盖的能力和下一步。没有实证的范围不能称“所有路书均通过”。

每张测试地图的核心事实块由write-map-report.mjs从该HTML、验收JSON和带地图哈希的实际浏览器结果生成；通用Skill结论仍由多输入独立测试决定。逐项核对自动报告与源数据，其他模型的解释性文本视为待核查草稿。没有某字段、原查询时间或完整执行日志时不能补造；仅有一个正确地图哈希也不证明浏览器脚本真的运行或道路通行。
