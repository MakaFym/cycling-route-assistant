# 导航分段规则

选择、检查或减少高德导航终点时使用本规则。

## 目标

以原GPX引导，尽量维持主要走廊、环线方向与必经点，允许经核查的局部差异，减少手动启动下一段的次数。不追求折线逐点重合。

交互地图负责保存和显示完整固定路线；高德只负责提供前往下一个关键导航终点的临时转向导航。

## 点位分类

### 路线形状点

按照固定折线的精度需要设置，可以很密集。不得把这些点显示成导航按钮或带编号的骑行任务。

### 沿途提示点

当某个位置有助于辨认方向或保障安全时，在地图或“即将到达的提示”列表中显示，例如：

- 普通但值得提醒的转弯；
- 危险、较差路面、无遮蔽路段或车流提示；
- 补给、厕所、地标、观景点或可选休息地点；
- 高德在当前导航段内已经能够正确通过的桥梁、道路入口或路口。

沿途提示点不得中断当前导航，也不得要求骑手重新启动高德。

算法按转向角度或道路名称变化筛出的点只能标为“转向提示候选”。只有核对固定轨迹与道路结构，确认该位置确实容易误入其他道路、错过指定入口，或需要提前处理明确的安全风险时，才称为“关键点”。补给点单列；是否兼作导航终点由计划停靠和路线保持需求决定。未核验的候选应可单独隐藏，不计入关键点数量。

### 导航终点

只有满足下列至少一个条件时，才把候选点提升为导航终点：

- 它是计划停靠点，骑手本来就会停车并操作手机；
- 它是实际起点、原路线接入点、原路线离开点、住宿点或终点；
- 它是必须经过的道路走廊、桥梁入口、轮渡、隧道、沿湖道路或可选支线的起止边界，而且高德可能绕开该路段；
- 路径测试证明，删除该点会导致导航路线明显偏离固定路线；
- 它是事先设计的恢复路线或撤退决策边界。

不能仅仅因为某处是急弯、道路名称变化、距离上一点达到某个公里数，或具有观赏价值，就把它设为导航终点。

若该点专门用于防止高德大段抄近，可标记为 `fidelity_anchor`。证据必须包含删除该点后的路线对比，以及全程双向覆盖率或连续偏离长度变化，不能只写“更贴近GPX”；保留后仍要继续测试相邻的其他端点，避免把一个修正扩散成过多切换。

## 选择流程

1. 完整保留原GPX，并取得实际起终点的高德道路方案，独立显示两条路线。
2. 把所有有意义的位置标记为沿途提示候选点。
3. 初始导航终点只保留不可缺少的接入点、离开点、计划停靠点和道路走廊控制点。
4. 使用高德或选定的道路网络，在相邻导航终点之间生成路线。
5. 核对主要走廊及必经道路，重点标经核实的易错岔路、主辅路、桥梁和沿湖入口、两线分离接合处。普通局部差异作提示，不为逐点贴合堆终点。
6. 逐个尝试删除非强制终点。如果删除后路线仍足够贴合，应将该点降级为沿途提示点。
7. 如果多个终点会让骑手在同一个路口、连续弯道或几分钟内多次切换，应合并为一个更有代表性的终点。

增设控制点后，还要检查到达与离开的道路方向。若高德为了“触碰”点位而产生原路返回，或仍走原先抄近路的走廊，这个点不能算有效约束，应调整到真正入口或寻找可通行的控制位置。单段出现“离开起点后又返回”“越过终点后折返”，或参考只有短距离而高德形成明显U形长绕行时，必须判为端点失败，不能用局部绕行审核放行。不要为了让候选公里数接近 GPX 而堆点。删除前后距离和道路说明相似只支持“可能可合并”，不能代替折线与入口核对。

定位断裂时可临时使用 `mandatoryKind: diagnostic_anchor` 把异常跨度二分或拆成少量连续探针，但这些点只用于查明高德路网在哪一小段改变走廊。诊断点不得直接进入完成版地图：先合并相邻可通过跨度，再对保留下来的候选终点重算完整导航组和删除跨度；只有仍能消除错廊且通过顺序、覆盖、端点返回和删除测试的点，才能改为 `fidelity_anchor`。这条规则防止“为了修一处回头路而让骑手连续手动切换导航”。

若已经把异常区间缩小到短连接，并且以该短连接精确两端进行高德骑行算路仍形成至少5倍的绕行，则将它记录为 `routeEngineGaps`，停止继续二分和堆端点。地图必须用独立图层显示GPX短连接、参考长度、高德绕行长度和证据日期，整体保持草稿，不得宣称存在连续高德导航。相邻可正常算路的跨度仍应尽量合并，以保存低切换候选，供用户决定改道、现场核对或更换导航工具。

## 遇到分时管控或入口限制

先核对通告日期、影响区间、时间窗、方向、适用车辆和是否有最新变更。不能把工作日晚间/周末限制说成全天封路，也不能把未明确自行车豁免推断成允许。日期未提供时保留带条件的时段说明，不擅自认定实际骑行日；条件方案本身不是通行审核通过。

把受影响段定位在真实算路几何上，先尝试保持环线目标与主要方向的合法入口或邻近平行公路，并重算相关段、删除跨度、距离和关键点。不能只做通告检索、普通道路侧别修正，就称已经穷尽针对管控的绕行。能在已授权渠道内完成的合理局部绕行自行处理并解释，保留原GPX对照；必须大幅改走廊、反向或放弃明确必经点时才请用户选择。若只能依赖具体日期或现场许可，给出确切路段、时间条件、已试替代及最小缺失信息，其他生成与测试继续做完。

## 可用性目标

- 普通一日骑行：通常需要 4–8 次手动切换。
- 常见分段间隔：约 15–30 km 或 45–90 分钟骑行时间。
- 开阔且路线稳定的道路：可以使用更长分段。
- 复杂城区或必须沿指定道路骑行的区域：只有为保持路线确实必要时，才使用较短分段。

以上是检查目标，不是硬性上限。为了保持固定路线可以增加终点，但每个额外终点都必须有具体理由，并通过“删除测试”。

纯距离型的最大间隔约束点只能作为最后手段。只有长分段已经表现出重新规划风险时才能添加，并标明它是“路线约束点”，而不是景点或普通转弯。

## 界面行为

- 把需要手动切换的高德导航段放在简短、醒目的主列表中。
- 把关键点、补给点和未核验的转向提示候选分别放在独立的可折叠列表或地图图层中；候选默认不遮挡主路线。
- 同时显示“下一导航终点”和“下一沿途提示”，但不得把提示点表现成必须切换导航。
- 骑手停车后，应能通过一个醒目的大按钮启动下一段高德导航。
- 从高德返回交互地图后，固定路线仍应保持可见。
- 不得要求骑手在移动中操作手机。

## 检查结果应报告

- 总路线距离；
- 必须手动切换的高德导航次数；
- 沿途提示点数量；
- 典型分段长度和最短分段长度；
- 每个异常短分段存在的原因；
- 每个非强制导航终点是否通过删除测试。
