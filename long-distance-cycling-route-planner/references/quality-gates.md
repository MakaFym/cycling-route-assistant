# 质量检查清单

最终交付前执行以下检查。无法完成的项目必须明确说明，不得默认已经通过。

本清单是具体地图与路线验收门槛，不是可复用 Skill 唯一完成条件。Skill 更新与独立测试另外执行[生成能力双层验收](reusability-acceptance.md)，逐项报告软件能力与具体路线证据，互不冒充。

## GPX-only 草稿门槛

GPX-only 不适用“完整可骑行地图”结论，但仍需通过自己的受限检查：状态固定为 draft；总里程、拓扑、方向为空；没有道路组成、导航段、导航链接、下一点或道路候选；GPX 1.0/1.1 的每个源段独立保留，段间无隐式连线；可选起点名称无坐标；界面明确缺少详细底图和道路服务。手机与桌面截图及自动事实报告须绑定当前 HTML 哈希。任何一项失败都是该草稿的软件缺陷，不能用“本来就不完整”略过。

这些通过只表示参考草稿按边界生成；道路接驳、路权、导航距离、在线详细底图和实机仍全部未验收。取得相应输入后必须回到下列完整门槛，不能继续沿用 GPX-only 结论。

## 交互地图完成门槛

以下任一项未通过，地图只能作为“未完成研究草稿”，不得以完整骑行地图交付：

- 实际起点至接入点、选定主线、必要返程形成连续的可骑行道路折线；没有用标记、直线或高德跳转链接代替接驳几何。
- 连通性不能只看道路图算法返回成功；逐段检查相对 GPX 的异常绕行、锚点偏移和未经确认的通行权限，拒绝把诊断和当成骑行总里程。
- 每个必需部分有独立的距离来源；完整总里程与组成部分相加一致。
- 高德导航段覆盖完整主线，不止接入段和返程段；每段链接真实可点，终点与地图一致。
- 完整地图的每段必须有成功的高德骑行结果、道路折线和里程证据；可来自官方 API 或已留存的官方网页结果。网页证据必须按组装流程复核，不能只有一个手填公里数或截图总数。路书 GPX 几何或 OSM 诊断和不能代替导航里程。未通过时禁用导航按钮。
- 手机首屏直接可见下一段高德主按钮，导航列表可操作且无横向溢出。
- 已用手机和桌面视口实际渲染，并核对地图详细底图、按钮与路线。
- 手机默认全程视图的路线应位于底部操作面板上方的可视区域；“全程”按钮和改变视口尺寸后仍需检查。

## 路线证据

- 每个主线分段都注明距离来源。
- 不得把直线距离或原始折线长度当成导航生成距离。
- 实时导航结果需要可复现时，应注明查询日期。
- 明确说明坐标系，并确认转换后的路线与底图道路正确对齐。
- 必须经过的道路、桥梁入口和关键路线锚点在地图上可见且确实经过。
- 完整原GPX与高德方案分色且同时显示。默认核对整体方向、主要走廊、必经入口和明显偏离，不要求逐点重合；局部绕行有具体对比证据，反向/错环/无意义折返不被“允许近似”掩盖。严格请求才用严格贴合验收。网页距离与对应独立几何仍须同走廊，不假称网页导出坐标。
- 参考主线达到5公里时，报告约20米等距采样的双向覆盖率和连续偏离长度。默认完成门槛为：原GPX到高德、高德到原GPX在200米内均不少于70%，在500米内均不少于85%；任一方向连续超出200米不得超过2公里，连续超出500米不得超过1公里。总体比例达标也不能掩盖一段长距离抄近或绕行。低于任一门槛说明整体约束不足，不能靠逐段“已复核局部绕行”的文字直接放行；应找最大连续偏离区，增加最少的路线形状端点后重新算路，再做端点删除测试控制切换次数。
- 每个导航段还要独立筛查端点返回和严重非顺序偏离。离开起点150米以上后在行程前85%内返回起点50米范围，或反向发生同类终点折返，直接拒绝。若顺序不兼容且p95偏离超过500米、长度比例超过1.8或低于0.55，也直接拒绝；这些异常不能由 `alignmentReview` 豁免，应移动到正确道路侧端点后重新算路。
- `diagnostic_anchor` 仅用于缩小高德路网断裂范围；任何组件段仍带此标记时都保持草稿。完成版必须先合并诊断跨度，并用新的完整导航组响应和端点删除测试证明保留终点确有必要。
- 精确短跨度的高德骑行结果达到参考长度5倍以上时，可记录为 `routeEngineGaps`，但必须带有效日期、原GPX短折线、双方长度和具体证据。存在路网断点时地图只能是明确标注的研究草稿；不能靠更多端点、直线补线或人工审核文字把它升级为连续导航。
- 已知的封路、轮渡、施工或通行限制如果可能使计划失效，应明确标出。

## 数字一致性

- 分段距离之和与对应单日总里程一致，误差不超过已说明的四舍五入范围。
- 独立导航组与组成部分的API算路值有米级差异时分别留源并显示差值，不强行分摊；超过10米拒绝自动通过。组成部分包含主线尾段/返程但未独立取证时不得全叫纯返程。
- 各日总里程之和与主路线总里程一致。
- 可选路线的距离单独报告，除非用户已经选择加入主线。
- 累计公里数按照路线顺序递增，并在终点达到报告的总里程。
- 时间估算与距离标记使用同一个路线版本。

## 地图行为

- 在有代表性的电脑和手机视口尺寸下，地图与控件均可正常使用。
- 定位服务不可用时，固定路线仍然可见。
- 当前位置功能能够正确处理权限拒绝和 GPS 信号较弱的情况，不得虚构位置。
- 距原GPX、距高德方案分别按最近折线计算并说明来源，不能以高德为0m暗示仍在GPX上，也不能只算到下一点。剩余里程只沿高德当前方案计算。
- 路线部分不连续时，不得在定位计算里添加地图没有显示的跨段直线；检查 GPX 首尾缺口，未经道路核对不得自动闭环。
- 剩余导航里程按各已核实分段的导航距离与段内进度计算，不能按全线几何比例均匀分配；该值仍是沿线位置估算，不是新一次实时算路结果。
- 下一点和剩余里程逻辑依据路线顺序，而不是只使用地理最近点。
- 实测定位后的下一已核实关键点、GPS 精度提示和导航段自动选中；路线自重叠、定位精度差或明显偏航时提示停车核对，不自动切换到可能错误的分段。
- 高德按钮使用正确坐标系，并指向预期的导航终点。
- 出发前，骑手能够看到高德可能重新规划路线的限制说明。
- 路线形状点、沿途提示点和导航终点在数据与界面中是三种独立类型。
- 沿途提示点不会要求重新启动高德，也不会出现在“必须切换”列表中。
- 自动检测的转弯或道路名称变化只作为候选；未核实的点不称为关键点。关键点、补给点、转向提示候选数量分别核对，候选图层可独立隐藏。
- 可选支线和未核实候选默认不覆盖主线；打开它们的图层不会改变主线里程、累计里程或必须导航段数。
- 导航终点只保留计划停靠点、主要道路走廊控制点、接入或离开点，以及删除后确实会导致路线明显偏离的位置。
- 每个非强制导航终点都完成删除测试；删除后仍能保持路线的，应降级为沿途提示点。
- 检查一日路线的导航终点数量和切换间隔是否符合低切换目标；每个异常短分段都有明确的路线保持理由。
- 同一路口或连续弯道附近的控制点已经合并，手机上的“必须切换”列表保持简短可操作。
- 在线地图放大后会加载或显示更多道路和地点细节，而不是只放大同一张低细节图。

## 在线与离线表述

- 使用“离线地图”一词前，必须在断网状态下测试。
- 如果断网后底图消失，即使 HTML、CSS 和 JavaScript 已在本地打包，也只能称为在线交互地图。
- 说明手机定位是否需要 HTTPS 和浏览器定位权限。

## 骑行计划

- 住宿点和补给点位于当前选定的路线版本上，并能实际到达。
- 长距离无补给区间和日照不足风险已经明确标出。
- 截止时间与撤退方案具体可执行，而不是泛泛建议。
- 如包含天气建议，应覆盖完整路线和骑行时段，并注明日期。
- 安全说明不得暗示地图可以取代交通规则、封路信息或现场标志。

## 隐私与发布

- 公开文件不包含精确家庭地址、私人住宿订单、账号标识、API 密钥或不必要的私人轨迹历史。
- 公开截图和文案使用与交互地图相同的路线版本和里程数据。
- 私人版本与公开版本有清楚区分。
- 用户明确同意上传目标和访问范围前，不得上传完整轨迹坐标和精确导航点。

## 最终交付说明

最终交付时说明：

1. 生成了哪些文件或服务；
2. 使用了哪个路线版本和距离来源；
3. 哪些功能需要联网；
4. 骑手出发前还需要确认什么；
5. 需要手动切换多少次高德导航，以及每个异常短分段存在的原因；
6. 哪些用户要求仍然无法实现或尚未验证。
