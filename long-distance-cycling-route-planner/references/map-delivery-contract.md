# 地图交付契约

仅在用户请求手机或电脑交互地图时读取。本文件规定可复用的界面结构和“完整地图”验收边界，不规定具体配色或某条路线的坐标。

## 两种交付状态

- **完整可骑行地图**：实际起点至接入点、选定固定主线、必要的返回实际终点三部分均有连续的可骑行道路几何和独立距离依据；高德分段覆盖这条完整主线；手机界面通过可见性和链接检查。
- **未完成研究草稿**：任一必需部分缺失或未核实。标题、里程和交付说明必须醒目标出未完成，不得把 GPX 折线长度写成完整骑行总里程，也不得说“地图已完成”。可以展示已核实部分，但应列出具体缺口和取得何种数据才能完成。

GPX-only 是“未完成研究草稿”的受限子类：只按源分段显示 GPX 参考线，`routeParts`、`navSegments` 为空，`totalKm`、拓扑和方向为 `null`。可保留一个未定位的起点名称，但不能据此生成坐标、标记或接驳。段间空白、未知方向和未知拓扑保持未知，界面明确说明没有详细底图和道路服务。

禁止用两个标记、直线、虚线或“点击高德后再看”代替道路接驳。不能获取可靠骑行道路路线时，诚实停在草稿状态并请求所需输入或访问条件。

使用随附组装器生成的单个 HTML 已内嵌 Leaflet 界面脚本；路线折线和控件可在断网时显示，但默认详细底图仍在线加载。任何“离线地图”宣称必须另行打包详细瓦片并在断网状态实测，不能把界面代码内嵌等同于离线底图。

## 地图数据

默认 `gpx-guided` 合理近似：原GPX为参考，高德尽量贴近主要走廊/途经点，局部差异经核查可以接受，不要求逐点复刻。只有严格请求用 `strict`。`originalGpx` 保留完整原始点列，不能用裁切的导航参考段代替原文件，也不能把OSM闭环候选标作GPX。原线与高德方案默认同时显示，图例/名称清楚，差异位置与易错入口优先作提示而非导航终点。完整地图同时显示全程双向覆盖率摘要（原GPX到高德、高德到原GPX的200米和500米覆盖）以及连续超出200米、500米的最长距离；这些指标只描述几何走廊，不代表路权或现场可骑行。

定位分别显示距原GPX、距高德方案；0m距高德不代表没有偏离GPX。总/累计/剩余以高德当前方案为依据，GPX长度另注几何来源。允许近似不替代道路审核，草稿仍不提供自动下一点指引。

使用导航组时，主地图与GPS投影必须采用`navigationRouteParts`的原始组合算路折线，不能显示略不同的独立组成响应却称距实际导航路线0米。`routeParts`仍在组成列表独立展示其角色与距离，内部边界不增加切换。正式`totalKm`采用当前导航组API总和，`compositionTotalKm`保留组成查询总和，米级差值明示。

把以下数据与页面样式分离，供同一界面复用：

- `routeParts`：按骑行顺序排列的去程接驳、路书主线、返程接驳。每部分包含 WGS-84 道路折线、距离、距离来源及是否核实。
- `navSegments`：沿完整路线排序的少量高德导航段。每段有名称、起点、终点、段距离、设置该终点的原因和 GCJ-02 高德链接。链接必须是可点击的实际 URI，不是按钮占位符。
- 各导航段保留独立 `points` 道路折线用于“当前段”聚焦；选择列表段或点击当前段后按真实段几何调整视图，不能仅更改下一终点文字，也不能用两端直线代替该段。
- 组成部分与导航段不必一一对应：可用`navigationGroups`把连续多个有独立API距离的`legs`合成一个导航任务，范围`firstLeg/lastLeg`为1-based且完整覆盖。组成部分仍各保留类型/几何/距离；导航任务另有真实合并响应，不能把合并的主线+返程公里数全叫返程。详见高德组装流程。
- `cues`、`supplies`：经核实的关键点或风险提示与补给点分开存放；`cues` 中真正的关键点标记 `kind:"key"`，并提供 WGS-84 `point`。
- 正式关键点必须有有效坐标；缺坐标的key条目会被省略并报告警告，纯文字安全提示可以没有坐标。`verified:false`明确表示未核实，组装时降为默认隐藏的turnCandidates，不计关键点、不参与自动下一关键点。`verified:true`本身不证明道路或事实真实；未给该标志仍须由Agent按实际依据决定kind分类。不要用未文档化的type:key代替kind。
- `optionalRoutes`、`turnCandidates`：可选支线需有自己的道路折线与单独距离，未核实的转向候选需有点位；两者默认不显示在地图上，也不计入固定主线里程或必须导航的段数。
- `totalKm`、`distanceBasis`：完整主线里程及出处。只在所有必需部分核实后提供完整总里程；各日与可选支线另行报告，不混入主线。
- `referenceRoutes`：与高德方案独立保留的固定参考折线，注明原GPX或本地候选出处。真实算路与参考线不一致时必须同时展示，不能把高德抄近路线叫作已经确认的固定主线。参考图层不计入里程、导航段和定位进度；全程视图同时容纳两者，差异未核实仍是草稿。

草稿中的定位若投影到 `routeParts` 候选折线，只能称“距候选路线（未验收）”，不能称距已确认固定线。草稿不提供下一关键点/导航段自动指引或剩余骑行里程；GPS位置与精度可供人工对照。只有完整已核实路线才使用“距固定路线”及正式进度。尤其要测试高德候选线上但离独立参考线数公里的位置，不能用“0m”暗示骑手仍在固定原线上。

模板中的 `__ROUTE_DATA_JSON__` 必须替换为合法 JSON 对象：`status` 为 `complete` 或 `draft`；`routeParts` 每项含 `type`（`outbound`、`main`、`return`）、`name`、`points`（按骑行顺序的 WGS-84 `[纬度,经度]` 数组）、`distanceKm`、`basis`；`navSegments` 每项含 `name`、`start`、`end`（WGS-84 坐标）、`distanceKm` 与 `reason`；`cues`、`supplies`、`optionalRoutes`、`turnCandidates` 独立。GPX-only 以 `originalGpx.segments` 和逐段 `referenceRoutes` 保存源段，不用单一 `points` 数组制造跨段连接。页面生成后不得保留占位符。模板会把高德链接所需坐标转换为 GCJ-02；如底图坐标系与模板默认设置不同，必须同步修改地图显示转换并核对道路对齐。

定位后页面按固定路线顺序寻找下一已核实关键点；GPS 精度差、明显偏离路线或路线自身重叠时，应提示骑手停车核对，不得据最近地理点武断跳段。定位可自动选中下一导航段，但不能自动启动高德或要求骑行中操作。

闭环接入点、终点或桥梁可多次出现。导航终点的沿线进度应按当前导航段的有序道路几何累积，不能将每个端点投影到全线最近处后当作段尾，否则后一次经过会倒退到去程。用唯一段内位置检查整环后半程与返程自动选段，同时保留重叠/弱信号的停车核对保护；定位模拟与真实手机验收分别记录。

路线部分首尾应在道路上相接。接入点可以不是 GPX 首点；为了更快接入可以选原路线中其他合适位置，但必须说明舍弃或替换原路线的哪一段，并重新计算主线闭环和返程。不得仅以几何最近点决定接入路线。

## 可复用界面布局

桌面以地图为主，侧边栏展示路线信息。手机以地图为主、屏幕底部紧凑操作区；全程视图的地图视口应为面板留出动态空间，不让标题、图例或面板遮挡路线。界面语义和控件顺序保持一致：

1. 首屏显示路线状态、总里程及依据，未完成时显示缺口。
2. 首屏显眼位置始终有“高德导航至下一终点”主按钮及该终点名称；不得放在默认折叠区、仅有弹窗或横向溢出区域。
3. 紧随其后显示“我的位置 / 距固定路线多远 / 下一导航终点 / 沿完整路线剩余里程”。定位权限拒绝时显示原因，不虚构位置。
4. 一个简短的导航分段列表；每段有独立高德链接，分段切换次数明示。查看关键点或补给点不要求切换高德。
   每个导航分段终点必须在地图上显示与列表一致的编号标记，并与关键点、补给点采用不同形状或图标；选择列表项或点击编号标记时，应同步突出并聚焦该分段。候选分段需使用不同的候选样式，不能冒充已确认导航终点。
5. 分开的关键点、补给、风险、可选路线图层或折叠列表；未核实转弯候选默认隐藏。
6. 地图始终显示整条固定主线，接驳与原路线可用颜色区分；支持全程/当前段聚焦和详细底图缩放。

可以因设备和用户视觉偏好调整排版，但不得删除以上功能。若要让不同 Agent 生成近似一致的视觉成品，应在 Skill 中提供去坐标化的 HTML/CSS 模板，并以模板为起点；没有模板时只能要求功能一致，不能声称像素级界面一致。

## 验收

长地点名或多个查询日期会增加面板高度；除常规手机/桌面外，应检查小屏及横屏。信息可以滚动，但主导航入口不应要求先滚动才能看到。紧凑视口优先显示主导航和常用按钮，完整里程来源仍保留在可滚动区域。

详细底图须检查实际截图，不以 HTTP 200 或 image 类型证明有道路内容。默认高德瓦片上限为已验证的18级；不能允许继续放大到空白瓦片。自选瓦片服务的上限另行实测，不把默认服务的观察推广到其他服务。在线检查脚本只验证加载、缩放与网络条件，最终道路细节仍需查看截图。

至少用一个桌面视口和一个约 390×844 的手机视口实际渲染。检查主按钮无需展开即可看到，面板无横向溢出，每个高德链接可点且终点与地图同名同坐标。检查每个导航分段都有唯一编号终点标记，编号与列表一致、选中状态可辨，并且不会与关键点、补给点混淆。检查完整路线和分段列表覆盖接驳、主线、返程，没有“只有接入/返程按钮”的缺口。检查分段距离之和与完整主线总里程一致，并验证坐标系转换和在线底图放大后的道路细节。失败时交付研究草稿，不得称作完成。
