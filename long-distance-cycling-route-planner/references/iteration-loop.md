# 自主更新与验证循环

仅在用户明确要求持续自主迭代到最终版本时执行。循环为：建立验收基线 → 复现失败 → 更新 → 从实际交付包测试 → 报告 → 分流失败 → 下一轮或最终交付。

## 验收基线

以当前用户需求、地图交付契约、质量检查清单及[双层验收](reusability-acceptance.md)为基线，分别列出生成能力与路线可骑行验收项；不以版本号或测试数量为完成条件。对照原始输入检查实际起点接驳、选定固定主线、必要返程、道路距离、低切换导航、关键点与补给分离、详细底图、定位与手机入口。已有用户选择不反复询问，不能静默更改固定路线来让测试通过。

失败清单每项记录：编号、要求、复现输入、证据、根因或待验证假设、是否需用户参与、修复与复测状态。按阻断完成程度处理，先修影响路线或验收可信度的问题。

## 每轮必须执行

1. 复现当前失败；能自动测试的，增加有效的失败用例。不能只测试字符串、标题或输出文件存在。保留原始输入与失败证据，不覆盖历史结果。
2. 修正实际根因并保持范围最小。不能删除失败测试、降低验收门槛、填造人工审核或导航证据、把真实用例替换成合成用例来得到通过。
3. 检查 Skill 结构和脚本回归；打包后解压到隔离目录，使用这个解压件继续测试，不能只在开发源码上测试。
4. 按改动风险运行真实输入、真实服务、桌面与手机视口测试，核对实际截图和按钮行为。合成数据用于边界回归；不能替代真实算路、固定路线贴合或真实 App 验收。
5. 路线变化后同步几何、分段、主线与可选距离、累计里程、时间、点位、定位进度及导航链接；核对方向、顺序、重复路段和折返，不只比较形状或总距离。
6. 主要问题解决后，在工具和授权允许时执行干净上下文的独立生成测试：仅提供当前 Skill 包、原始材料及当前用户需求，不提供旧成品、历史答案或预期结论。核对实际产物。其他模型或 Agent 没有运行时，不能宣称跨 Agent 通过。
7. 记录并告知本轮结果，然后决定下一步。报告不需要用户批准才继续下一轮。

环境依赖失败属于需要解决的执行问题；可用现有依赖、隔离环境或安全替代工具时自行处理，不直接归为用户阻塞。失败反复出现时重新定位根因、换验证路径；重复同一无效尝试不算继续推进。

## 失败分流与停止条件

- **能自主解决**：代码、规则、模板、包内依赖说明、测试覆盖、链接、界面、坐标转换、距离同步、可通过已授权渠道核对的路线或点位。报告后直接继续更新和测试，不询问“是否继续”。
- **确实需要用户参与**：必须决定是否改变固定路线；缺少无法可靠推断的起点或出口信息；必要授权、账号、服务凭据；真实手机操作或现场道路确认。先完成所有不受影响的工作，说明已尝试的安全替代方案，只请求最小必要输入。普通失败或尚未尝试替代方案不能算用户阻塞。
- **用户取消、要求暂停或系统执行限制**：如实保留断点、最后证据和下一步，不能宣称会在已结束的回合后台继续运行。
- **全部约定验收项通过**：交付最终包、地图、测试报告、距离来源和平台限制。人工或实机验收没有完成时，明确列为待用户验证，不能称为全部通过。

默认坚持完整原GPX参考、主要道路走廊和已约定必经点，而不是逐点锁定高德。允许有具体证据的局部绕行；不得借此放过逆向环线、顺序异常或大段折返。严格贴合仅在用户明确要求时启用。不会因循环反复运行而消除平台本身的限制，不承诺连续锁定自定义高德路线。

## 每轮结果格式

- 轮次与版本、此次修正及对应失败编号。
- 测试环境、使用的解压包、原始输入和实际执行项目。
- 通过、失败、未测分别列出；提供报告、截图或原始结果位置。
- 剩余失败、是否需用户参与、下一轮将处理什么。

无论单元测试通过多少项，未通过具体路线验收的地图仍为未完成草稿。Skill生成能力按独立输入矩阵另外报告，可以在明确范围内通过；不能据此批准路线，也不能因一条路线待现场核查无限停止可复用性测试。取证页、研究地图与候选里程均不能冒充最终导航地图。公共发布、仓库推送、上传新增服务或付费不属于本循环的自动新增权限。
