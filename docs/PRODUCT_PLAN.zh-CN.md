# 骑行路线助手：微信小程序产品路线 v0.1

日期：2026-11-17  
状态：产品决策草案，尚未进入开发

## 1. 决策结论

优先验证微信小程序，但不把它定位为完整导航软件。

产品形态调整为：

- 用户侧：微信小程序，负责查看固定 GPX、路线核验、当前位置、偏离提醒、关键点、补给与风险、分段导航入口和路线分享。
- 生成侧：现有 Skill 保留为内部路线生产引擎，不单独售卖。
- 管理侧：先使用本地/网页管理工具上传 GPX、审核双路线和发布路线；普通骑手不直接面对复杂的生成过程。
- 高德侧：负责路网算路和可用分段；不承诺严格沿 GPX，也不承诺微信内一定能无缝拉起高德 App。

如果未来要求后台持续定位、语音导航、自动换段、真正离线地图或锁定 GPX 导航，再评估独立 App。

## 2. 目标用户与核心任务

目标用户：拿到别人路书或 GPX，但起点不同、不使用专业轨迹导航、平时主要使用高德的长距离骑行者。

核心任务：

1. 从自己的实际起点合理接入原路书。
2. 始终看到完整 GPX 原线，防止高德擅自改变骑行意图。
3. 对可导航部分提供尽量少的高德分段。
4. 提前暴露偏离、回头路、疑似路网断点和未核实通行点。
5. 在停车休息时快速确认当前位置、距原线多远、下一关键点和备用绕行。

## 3. 为什么不是继续售卖 Skill

普通骑手购买的是路线结果和途中体验，不是 Agent 提示词、脚本和生成流程。单独售卖 Skill 存在以下问题：

- 用户仍需安装或理解 Agent 环境。
- 生成结果需要道路核验、坐标转换、地图发布和手机适配，无法靠一段说明完成。
- 高德路网、实际通行和 GPX 之间存在不确定性，必须由产品界面清楚表达证据等级。
- 更新 Skill 不能自动更新已发布路线，服务端路线版本管理更适合长期维护。

因此 Skill 应成为内部能力和质量规则，而不是主要商品。

## 4. 小程序为什么适合 MVP

适合之处：

- 无需安装，微信群、二维码和路线卡片方便分享。
- 微信原生 `map` 组件支持 `markers`、`polyline`、`include-points` 和当前位置显示，可承载 GPX 与高德双路线。
- 高德微信小程序能力可以请求骑行路线数据，适合生成并展示分段候选。
- 用户本来就计划停车查看交互地图，小程序前台定位与路线核对符合该使用方式。

不适合直接承诺的能力：

- 微信内置浏览器可能无法成功调起高德，必须先做 Android/iOS 真机验证和失败回退。
- 后台持续定位需要位置权限、`requiredBackgroundModes` 配置以及适用类目审核；骑行路线助手是否能获批不能预设。
- 小程序不应在 MVP 阶段承诺持续语音导航、后台自动换段或完整离线地图。
- 长距离 GPX 的折线点数、渲染速度和内存表现没有在目标手机上验证，需要真机压力测试。

## 5. MVP 功能边界

### 必须包含

1. 路线列表与路线详情。
2. GPX 原线完整显示，并单独显示来源与参考里程。
3. 高德候选路线作为第二图层，可单独开关。
4. 实际起点到 GPX 的接入路线。
5. 当前位置、定位精度、距 GPX 原线距离。
6. 下一关键点、关键点类型、距关键点距离。
7. 导航分段、风险点、补给点分别展示。
8. 异常分类：普通偏离、回头路、短路网断点、明显绕行、现场待确认。
9. 分段高德入口；失败时提供复制终点、查看端点和小程序内继续看图的回退流程。
10. 路线版本号、生成日期、距离来源和未验证声明。

### MVP 明确不做

- 后台持续轨迹记录。
- 全程语音转向导航。
- 自动在后台切换下一导航段。
- 真正离线底图。
- 用户社区、排行榜、骑行数据社交。
- 自动宣称某条小路现场可通行。
- 直接向普通用户开放未经审核的自动 GPX 生成结果。

## 6. 建议架构

```text
路线创建者/运营者
        │ 上传 GPX、起点、行程要求
        ▼
路线生产引擎（现有 Skill + 固定脚本）
        │ 解析、坐标转换、高德算路、偏离检测、风险分级
        ▼
人工审核台
        │ 接受/调整分段，标注未验证项，冻结路线版本
        ▼
路线 API / 数据存储
        │
        ▼
微信小程序
GPX 原线 + 高德线 + 定位 + 关键点 + 分段入口
```

原则：生成、审核、发布分离。未经审核的候选路线不能直接变成用户可骑行路线。

## 7. 三阶段路线图

### 阶段 0：技术可行性样机

目标：只验证小程序是否适合，不建设完整后台。

使用一条经过脱敏的长距离测试路线，完成以下四项：

1. 原生小程序地图同时绘制 GPX 与高德两条线。
2. 获取前台位置并计算距 GPX 距离。
3. 显示下一关键点和一个路网断点。
4. Android、iOS 各测试一次高德入口及失败回退。

阶段门槛：四项任一无法形成可接受替代方案，则暂停小程序方向。

### 阶段 1：私人 MVP

目标：本人和少量邀请用户真实使用。

- 路线列表、详情、双路线、图层开关。
- 关键点/补给点/风险点分类。
- 5～10 个低切换导航分段。
- 路线版本与生成证据。
- 位置、偏离距离、下一关键点。
- 简单的路线发布后台，生成结果必须人工审核后上线。

不接支付，不公开承诺导航能力。

### 阶段 2：小范围验证

目标：验证它是否比“高德 + 截图/普通网页”更省事。

建议测试：至少 10 条不同类型 GPX、5～10 名真实骑手、Android/iOS 均覆盖。记录：

- 路线打开成功率。
- GPX 显示完整性。
- 高德入口成功率及回退成功率。
- 每 50 km 人工切换次数。
- 未标记的大偏离数量。
- 用户停车核对一次所需时间。
- 用户是否愿意再次使用或分享。

达到门槛后再决定是否做公开小程序、收费路线或路线生成服务。

## 8. 量化验收与停止条件

### 建议验收线

1. GPX 原线：输入点顺序和路线形状 100% 保留；坐标系转换误差单独记录。
2. 异常透明度：所有超过设定阈值的高德偏离、回头和路网断点均必须在界面出现，不能静默替换。
3. 操作负担：默认方案目标不超过每 50 km 3 次手动换段；特殊路况必须解释原因。
4. 真机兼容：Android/iOS 均能完成查看、定位、返回路线；高德无法拉起时必须有可用回退。
5. 性能：目标中低端手机打开长路线后可顺畅缩放和切换图层，具体帧率、首屏时间和最大点数由样机实测确定，不能先编造指标。

### 立即停止或转向独立 App 的条件

- 高德入口在微信环境中大面积失败，回退流程仍明显打断骑行。
- 小程序类目无法获得所需定位权限，前台定位也不能满足核心体验。
- 长路线必须过度抽稀，导致关键弯道或路线判断失真。
- 为保持 GPX 需要大量导航分段，实际操作不比行者或普通高德方便。
- 用户只认可连续语音轨迹导航，而不接受停车核对模式。
- 小范围测试表明用户不会重复使用或分享。

## 9. 商业化顺序

1. 先做私人免费样机，验证技术硬门槛。
2. 再做邀请制 MVP，验证是否真的降低操作负担。
3. 验证后可尝试：单条路线制作服务、路线作者工具、精选路线包或会员路线库。
4. 不先卖 Skill，不先开发完整 App，不先接支付。

商品应是“经过核验、能在手机上实际使用的路线体验”，不是 GPX 转换脚本本身。

## 10. 下一步任务

1. 用现有测试路线制作不联网后台的原生小程序样机。
2. 优先测试高德入口，而不是先完善页面视觉。
3. 测试微信位置接口的主体、类目和权限申请可行性。
4. 在两台真实手机上验证双路线渲染、定位和返回流程。
5. 根据结果做 Go/No-Go 决策，再决定是否建设路线后台。

## 11. 官方能力依据

- [微信小程序 map 组件](https://developers.weixin.qq.com/miniprogram/dev/component/map.html)：支持标记、折线、视野包含点和当前位置显示。
- [微信小程序 getLocation](https://developers.weixin.qq.com/miniprogram/dev/api/location/wx.getLocation.html)：离开小程序后不能调用，且位置接口涉及声明、类目与审核要求。
- [微信小程序后台定位](https://developers.weixin.qq.com/miniprogram/dev/api/location/wx.startLocationUpdateBackground.html)：需要后台位置授权、配置和适用类目。
- [高德微信小程序骑行路线规划](https://lbs.amap.com/api/wx/guide/route/route)：可请求骑行路线并取得折线和距离数据。
- [高德 URI 路径规划](https://lbs.amap.com/api/uri-api/guide/travel/route)：支持骑行模式，但官方提示微信等内置浏览器可能无法成功调起。
